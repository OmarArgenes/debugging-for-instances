# DFI-001 — WordPress header element: locating the real origin

## Evidence status

**Mode:** exploratory + validation  
**Stack:** WordPress, browser DevTools / Console  
**Historical source:** engineering chat later formalized as a foundational DFI example  
**Outcome:** origin path identified in the original investigation; exact historical command/output was not preserved

## Observable problem

A visible header element had to be changed or removed. The documentation/expected administrative route suggested one configuration location, but inspecting the live element did not support that assumption.

## Initial hypothesis

**H1:** the element was generated by the expected WordPress/theme administrative option.

## Diagnostic path actually documented

The investigation followed the live rendered element instead of changing configuration speculatively:

1. inspect the element in DevTools;
2. inspect its DOM structure, classes and attributes;
3. relate those identifiers to theme/plugin/script behavior;
4. compare the observed implementation with the expected admin route;
5. move to the configuration path supported by the evidence.

## Preserved evidence

The foundational record preserves the following facts:

- the live element was inspected through **DevTools / Console**;
- structure, classes and behavior did not match the initially assumed administrative route;
- the initial hypothesis was rejected;
- another configuration path was followed and the element's real origin was identified.

## Diagnostic artifacts

**Exact historical Console script:** not preserved.  
**Exact selector / DOM fragment:** not preserved.  
**Exact admin option ultimately responsible:** not preserved in the public historical record.

No later WordPress header/menu investigation is substituted here as if it were the original DFI-001 artifact.

## Decision

The important evidentiary transition was:

`expected admin route` → contradicted by live DOM evidence → `trace rendered origin` → identify the actual configuration source.

## Verification

The original case was recorded as successfully locating the real origin. A separate exact before/after verification artifact was not preserved and is therefore not reconstructed.

## Limitations

This case is methodologically important but evidentially incomplete. It demonstrates the DFI reasoning pattern, not a fully reproducible technical experiment.

## DFI significance

DFI-001 establishes a core rule used in later cases: **do not keep editing the place that documentation suggests when the running system provides evidence that the behavior comes from somewhere else.**
