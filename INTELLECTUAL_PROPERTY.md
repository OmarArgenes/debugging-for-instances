# DFI — Intellectual Property and Rights Strategy

> This document is a project record, not legal advice.

## 1. What this repository is intended to protect and document

The DFI project separates the **concrete expression of the work** from the broader ideas and techniques discussed by the methodology.

The following materials have a concrete, versioned expression and form part of the public authorship record:

- the foundational DFI document;
- the written definition, terminology, diagrams and methodological specification;
- original templates, schemas and examples;
- the repository documentation and website;
- future original software source code created for DFI tooling.

## 2. Copyright

The DFI documentation is distributed under **CC BY-NC-ND 4.0** unless a file states otherwise. Reference source-code examples are separately identified under the MIT License.

Public licensing does not erase authorship. The canonical citation and author attribution must remain clear.

Bolivian SENAPI states that copyright protection arises with the creation of the work and that registration provides greater legal certainty. The project therefore keeps SENAPI registration as a separate legal-registration track.

Official reference: https://www.senapi.gob.bo/derecho-de-autor-y-derechos-conexos

## 3. Methodology versus abstract idea

DFI does not rely on a claim that every underlying debugging idea is new or exclusively owned. The scientific antecedents documented in the foundational work remain prior art.

The protectable and attributable contribution is the concrete DFI expression and its documented integration: terminology, operating model, workflow, artifacts, governance, cases, implementation materials and future software.

## 4. Name and identity

The names **Debugging for Instances** and **DFI** may be evaluated separately for trademark / distinctive-sign protection. Trademark registration is distinct from copyright registration.

## 5. Software

If a DFI Analyzer or other software implementation is developed, it should be versioned and documented separately and may be registered as software where appropriate. Software registration should not be confused with ownership of the abstract debugging methodology.

## 6. Evidence of priority and provenance

The project preserves multiple independent public references:

- Zenodo DOI and publication timestamp;
- ORCID work association;
- GitHub commit history;
- GitHub Pages publication;
- Search Console verification and indexing submission;
- future SENAPI registration records.

Together these records strengthen traceability and help demonstrate when specific DFI materials were publicly documented.
